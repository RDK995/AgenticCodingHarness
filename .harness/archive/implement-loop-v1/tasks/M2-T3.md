TASK  M2-T3 — per-step time limit: terminate, kill after grace, record a failed step
Tier: Mid (sonnet) — reason_code ORDINARY_IMPLEMENTATION: a deadline in the existing step wait loop that reuses the already-tested `terminate_step`; bounded, with a clear test oracle.

Goal:
A step session that runs longer than the step time limit is ended through the existing `Driver.terminate_step` (SIGTERM to the step's process group, SIGKILL after the grace period if still alive) and judged as a failed step, recorded in loop.log. The limit is 3 hours (10800 seconds) by default and overridable per start with a `--step-timeout <seconds>` option on `start`, persisted in `.harness/loop/config.json` like `grace`.

Relevant Requirements:
.harness/requirements.md FR5, FR6(d) (lines 34-48), Edge Cases (lines 143-162). Milestone .harness/milestones.md M2 (Outcome "Settled at planning" paragraph, M2-AC5).

Acceptance Criteria:
- M2-AC5: A step that exceeds the step time limit (3 hours by default, overridable per start) is terminated, killed after the grace period if still alive, and recorded in the loop log as a failed step.

Decisions already taken (do not re-decide):
- Constant `DEFAULT_STEP_TIMEOUT = 3 * 60 * 60`. `start --step-timeout` (type float, default DEFAULT_STEP_TIMEOUT) stored as `step_timeout` in config.json; the driver reads it with that default.
- In `Driver.run_step`'s wait loop, track a monotonic deadline; when exceeded, log "step N exceeded time limit <seconds>s: terminating" and call `terminate_step()` (which already logs SIGTERM and the SIGKILL-after-grace line).
- A timed-out step is a failed step regardless of state changes: its outcome is "failed step: time limit <seconds>s exceeded", logged as "step N outcome: failed step: time limit ...". Under M2's interim rule (from M2-T2) a failed step stops the loop; the outcome.json outcome is that failed-step text. Thread the timed-out fact into the judge function (e.g. an extra `timed_out` parameter) so the judge, not ad-hoc code, decides.
- Do not implement two-consecutive-failure counting (M4).
