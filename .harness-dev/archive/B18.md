## B18 — Read discipline at runtime (post-V1)

Status: DONE

Specified in `docs/implementation-plan.md` §41. Triggered by an observation on a
real project: the orchestrator's first turns consumed ~93k tokens before any
implementation began, with `architecture.md` 500 lines, `milestones.md` 639 and
`requirements.md` 297 read in full. All three causes are gaps in how B16 was
applied, not new defects.

### Decisions

- **The archiving mechanism is unchanged; only when it is checked.** The rule in
  `milestones-template.md` was correct and is untouched. The defect was that
  `agents/orchestrator.md` invoked it only "before you finish", so an oversized
  file was read in full at the start of every milestone and trimmed at the end —
  the saving landing on the next session, never on the one that paid.

- **Ranged reads stop at the review boundary.** The obvious reading of §39 item 4
  is "read less, everywhere". Applied to a reviewer that would be actively
  harmful: a verdict from a partial look is still formatted as a verdict, and
  nothing downstream can tell the difference. `runtime-contract.md` already names
  this as the harness's worst failure. The guidance is therefore scoped to
  reference material, with the diff, the code it touches, and the tests read in
  full — stated in both `orchestrator.md` and `reviewer.md`.

- **`skills/implement/SKILL.md:75` deliberately left alone.** The final review is
  still handed every archived milestone. It is the peak cost, recorded as such in
  B16, but a holistic review plausibly needs the whole picture — trimming it would
  weaken verification to save tokens, which is the trade B18 exists to refuse.

### Follow-ups

- **Recon has no durable store, by design — but the toolchain arguably should.**
  `agents/orchestrator.md` refuses to persist reconnaissance ("not an artifact in
  itself"), correctly: a stored recon document is an agent *conclusion*, and
  trusting it later is what the harness forbids. But no template captures the test,
  lint, type-check and build commands, so every milestone rediscovers them by
  reading `pyproject.toml`/`Makefile`/config. Those are ~5 near-static lines and a
  *pointer*, not a conclusion — a wrong command fails loudly the moment it runs.
  Highest value-per-byte thing the harness could persist. Candidate B19, inside the
  existing templates rather than as a new file.

- **Existing codebases re-derive their map every milestone.** The architect skill
  is for new projects; an existing codebase skips it, so nothing durable exists and
  recon rebuilds the same understanding forever. `architecture.md` is effectively a
  recon cache that a human agreed to — which is what makes it trustworthy where
  agent notes would not be. A "map an existing codebase, then have a human agree
  it" path would convert recurring cost into a one-time cost with no new storage
  format. Larger than B19; worth specifying properly.
