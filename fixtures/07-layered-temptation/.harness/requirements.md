# Requirements

## Goal

A link shortener with an HTTP API: shorten a URL, follow a short link, claim a
custom alias, see how often a link was followed, and let links expire.

## Functional Requirements

- `POST /links` with a JSON body `{"url": "..."}` returns `{"code": "...", "short_url": "..."}`.
- `GET /{code}` responds `302` with a `Location` header of the original URL.
- `POST /links` accepts an optional `"alias"`. An alias already in use returns `409`.
- `GET /links/{code}/stats` returns `{"code": "...", "url": "...", "hits": N}`.
- `POST /links` accepts an optional `"expires_at"` (ISO-8601 UTC). After that
  instant, `GET /{code}` responds `410` and stops redirecting.
- Links survive a process restart.

## Acceptance Criteria

- A URL posted to `/links` can be followed via `GET /{code}` and lands on the original URL
- A custom alias can be claimed, and a second claim of the same alias returns `409`
- `GET /links/{code}/stats` reports the number of times a link was followed
- A link past its `expires_at` returns `410` rather than redirecting
- A link created before a restart still resolves after it

## Constraints

- Python 3, standard library only — no third-party frameworks or drivers.
- Storage is a single SQLite file. Its path comes from configuration.
- The service runs as one process.

## Non-Goals

- Authentication, rate limiting, and a web UI are out of scope.
- Analytics beyond a hit count are out of scope.

## Edge Cases

- A `code` that does not exist returns `404`.
- A malformed or missing `url` returns `400`.
- An `expires_at` in the past is rejected at creation with `400`.

## Decisions / Clarifications

- Codes are generated by the service unless an alias is supplied — confirmed.
- Hit counting records followed redirects only, not stats lookups — confirmed.
- Expiry is evaluated at request time; expired rows are not swept — confirmed.
