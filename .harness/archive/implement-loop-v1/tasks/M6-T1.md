Design (settled — implement exactly this):

Where the data lives:
- state.json: `milestones[<id>]` objects with `outcome` (str), `status` (str), `criteria` (list of {"id","text",...}), `tasks` (list of {"id", "routing": {"tier": "Cheap"|"Mid"|"Top", ...}, ...}), `reviews` (list of {"tier": "Mid"|"Top", ...}). Any of these may be absent or the wrong type; treat that as empty.
- milestones.md: each milestone is a section starting with a line `## <id> — <name>` (an em dash `—`; also accept ` - ` hyphen) and running to the next line starting with `## `. Inside it, subsections start with `### <Heading>` and run to the next `### ` or the section end. Subsections used: `### Outcome` (prose paragraph) and `### Acceptance Criteria` (lines like `- [ ] M6-AC1 text` or `- [x] M6-AC1 text`).
- Match the section by exact id: `## M6 — ...` must not match `## M6a — ...`.

1. `milestone_start_summary(project: Path, identifier: str) -> str`
   - name: text after the dash in the section heading; else state.json `outcome`; else the identifier.
   - goal and scope: the `### Outcome` body with all whitespace runs (including newlines) collapsed to single spaces; else state.json `outcome`; else omit the line. (The milestones template has no separate scope heading: `### Outcome` states both what the milestone achieves and what it builds, so it is sent under one label.)
   - criteria: from state.json `criteria` as `<id> <text>` lines when that list is non-empty; else from the milestones.md `### Acceptance Criteria` list items with the leading `- [ ] ` / `- [x] ` removed; else the single line `(none recorded)`.
   - Exact shape (lines joined with "\n"):
     ```
     <id> starting — <name>
     Goal and scope: <goal and scope>
     Acceptance criteria:
     - <criterion 1>
     - <criterion 2>
     ```
   - Do not label it with the project and do not truncate: the existing `prepare_message` (called by `notify`) already does both.

2. `milestone_finish_report(project: Path, identifier: str) -> str`
   - name: as above. result: state.json `status` (e.g. `DONE`); else `UNKNOWN`.
   - tasks: `len(tasks)`; count each task's `routing.tier` among exactly `Cheap`, `Mid`, `Top`; a task whose tier is missing or anything else counts as unrecorded.
   - reviews: the distinct `tier` values of `reviews`, in first-seen order, joined with " and ".
   - Exact shape:
     `<id> <result> — <name> — <N> task(s): <c> Cheap, <m> Mid, <t> Top; reviewed by <tiers>.`
     - `task` when N == 1, else `tasks` (`0 tasks`).
     - Always show all three tier counts, in the order Cheap, Mid, Top, even when zero.
     - If any task is unrecorded, append `, <u> unrecorded` after the Top count.
     - With no reviews, replace `reviewed by <tiers>` with `no review recorded`.
     - Example: `M3 DONE — Accounts can be listed — 7 tasks: 4 Cheap, 2 Mid, 1 Top; reviewed by Top.`

Both functions: a missing, unreadable or invalid JSON / markdown file means that source is empty; never raise.
